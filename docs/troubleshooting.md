# Troubleshooting

Back to the [README](../README.md).

| Symptom | Cause | Fix |
|---|---|---|
| `ficelle: unknown observation key '...'` | Your observation dict has a key the checkpoint doesn't expect (typo, wrong camera name, stray key). | Print `client.metadata["observations"]` and match keys exactly. |
| `ficelle: missing observation key '...'` | Your observation dict is missing a key the checkpoint requires. | Same as above — `client.metadata["observations"]` lists every required key. |
| `ficelle: '...' has shape [...], expected [...]` | Wrong resolution, missing/extra `n_obs_steps` stacking axis, or wrong array shape. | Resize/crop images and reshape arrays client-side to match `frame_shape`/`wire_shape` from the metadata. |
| `ficelle: '...' has dtype ..., expected uint8/float32` | Sent e.g. `float64` state or `int32` image. | Cast client-side: images to `np.uint8`, states to `np.float32`. |
| `jpeg_quality requires an image codec: pip install opencv-python-headless (or pillow)` | `jpeg_quality=` was passed but neither codec is installed. | `pip install opencv-python-headless` or `pip install pillow`. |
| `resize requires an image codec: pip install pillow (or opencv-python-headless)` | `resize=True` was passed but neither codec is installed. | Same fix as above — either codec works for both features. |
| `ValueError: server at ... does not advertise resize (its policy doesn't resize internally)` | `resize=True` was passed, but the served policy doesn't resize internally (e.g. pi0fast). | Drop `resize` and use `jpeg_quality` alone. |
| `PolicyServerError: server at ws://... rejected the api key — check --api_key on both sides` (raw curl/HTTP clients instead see a `403` body of `ficelle: invalid or missing api key`) | Server was started with `--api_key` but the client didn't pass a matching one (or vice versa). | Pass the same `api_key=...` to `PolicyClient(...)` as `--api_key` on the server. |
| `--api_key is not supported with --transport iroh` (server refuses to start) | `--api_key` was passed together with `--transport iroh`. | Drop `--api_key` — over iroh, access control is possession of the ticket, not a shared secret. |
| `ValueError: iroh transport needs the extra: pip install 'ficelle-client[iroh]'` | `open_client`/`IrohPolicyClient` was called with a ticket but the `iroh` package isn't installed. | Install the extra: `pip install "ficelle-client[iroh]"`. |
| iroh client raises an error building the endpoint from the ticket string (malformed/truncated ticket) | The ticket was cut off, mistyped, or copy-pasted from the wrong log line — it's a long opaque string and easy to truncate. | Re-copy the full `iroh ticket: endpointv1...` line the server logs on startup; don't split it across lines. |
| First request to a large model (e.g. a flow VLA) takes 30+ seconds, or `PolicyServerError: inference timed out after ...s (link degraded or server stuck)` on the very first call | The server normally pays this CUDA/model warmup cost once at startup (see [Startup & the first request](remote-access.md#startup--the-first-request)); if warmup was skipped for this checkpoint, the first request pays it instead — not a hung link either way. | Raise the client's `infer_timeout` to at least 60s for VLA-class models (default is 5s) — subsequent requests are fast. |
| Latency much higher than the README's numbers, or multi-second stalls over iroh | iroh fell back to the relay path instead of a direct (hole-punched) connection — the free relay is throttled (~1 Mbps). | Always pass `jpeg_quality=90` over iroh. Check whether the connection is direct or relayed; see [remote-access.md](remote-access.md) for the direct-vs-relay data. |
| pi0fast output is garbage / repeats itself / degenerates | Currently broken upstream in LeRobot — free-running generation collapses. This is a model/training issue, not a ficelle bug. | Not a current example; use a diffusion or flow-VLA (e.g. π0.5) checkpoint instead. |
| `ficelle: server at ws://... does not support jpeg encoding` | The server is running an older version of ficelle that predates JPEG support. | Upgrade the server to the current version, or drop `jpeg_quality` from the client. |
| Client logs `waiting for server at ...` forever | Wrong host/port, a firewall in the way, or the server is bound to a different interface than the client is reaching. | Confirm the server's startup log ("serving on ws://...") matches the address the client is dialing; check firewalls; see [remote-access.md](remote-access.md). |
| Server fails to start, error mentions `AutoProcessor` / tokenizer loading | Known `transformers` v5 + `physical-intelligence/fast` Hub packaging bug: the tokenizer repo referenced by the checkpoint's config isn't resolved correctly unless the checkpoint points at its **own** fitted tokenizer repo. | Check the checkpoint's config references its own fitted tokenizer repo, not a shared/generic one. |
| Metadata shows `"fps": None` | The checkpoint has no `train_config.json` (or it points at a training dataset that's unreachable), so ficelle couldn't look up the training frame rate. | Harmless — `fps` is informational only and isn't used by the server or client for anything. |
